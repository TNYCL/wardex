# MCP Events (optional, Wardex 0.2)

MCP Events is an additional delivery adapter. It does not replace generic
`[[webhooks]]`, their payload, routing, reload behavior or HMAC signature.
It is disabled by default. Existing tools and clients remain available.

## Enable deliberately

Set `[mcp_events] enabled = true` in the daemon configuration and restart
through your approved deployment procedure. Changes require a restart;
webhook reload does not enable this feature. Recreate the stdio MCP proxy and
rescan the plugin after an approved upgrade: a running proxy caches startup
capabilities. Tunnel/proxy restarts remain a separate operational approval.
New databases are created with
mode 0600. Existing databases and their parent directory must already have
owner-only permissions (0600 and 0700); Wardex refuses unsafe permissions
rather than changing them. Protect WAL/SHM files and backups too.

Subscriptions persist callback URLs and signing secrets in SQLite. These
values are sensitive and are **not encrypted at rest**. No additional
persistent credential is generated by Wardex. Do not copy this database to
less protected storage. URLs, signing material and receiver response bodies
are excluded from logs and diagnostics.

All settings and bounds appear in `deploy/wardex.example.toml`. TTL grants
are finite: omitted or null `ttlMs` receives the configured default; numeric
requests are capped at that default with a minimum of 60 seconds. The default
is one hour. Limits, including callback verification rate, bound resource use.

## Discovery and the wire contract

The ChatGPT profile uses MCP 2026-07-28 and `capabilities.events` on
`server/discover`. Wardex provides native `events/list`, `events/subscribe`
and `events/unsubscribe` methods on the same authenticated MCP endpoint as
tools. They are not tools named after those methods. Only webhook delivery
is advertised. Polling, streaming, `gap` and `terminated` envelopes are not
implemented for this integration.

The locked rmcp 3.5.1 already supports MCP 2.0, custom requests and metadata
validation, but its capability type has no `events` field. A narrow wire
adapter adds that field to discovery, with HTTP and stdio contract tests.
It preserves rmcp authentication and protocol checks; there is no SDK fork.
MCP 2.0 HTTP requests must carry the protocol's method/version headers and
request metadata. Legacy tools continue using their existing protocol.

The ChatGPT guide currently assigns `CallbackEndpointError` code -32015;
the linked experimental design sketch uses -32027. This implementation
uses -32015 for the ChatGPT profile. Recheck the profile before changing it.

## Ownership and filters

Wardex retains its existing single-owner model: one bearer token for HTTP,
and a mode-0600 local socket for stdio forwarding. Both map to the daemon's
owner principal. A tunnel transports requests; it does not turn untrusted
`_meta`, `agent` or `task` fields into authenticated end-user identity.
Clients sharing this boundary can manage the same sessions and subscriptions.
This is not multi-user isolation; use separate trusted instances where needed.
No bot registration is required. Labels are optional filters, not permissions.

On bearer credential rotation or owner-access revocation, increment the
non-secret `authorization_epoch` and restart through the approved procedure.
Startup cancels old-generation queues and clears their signing material before
workers start; only the current principal can enqueue/deliver. A shared token
cannot identify one disconnected end user automatically. Unsubscribe, finite
TTL and this explicit global revocation are the available ownership controls.

The subscription identity hashes the principal, normalized callback URL,
event name and canonical arguments. Repeating the identity refreshes it;
changing a component creates another subscription. `events/unsubscribe`
uses the original name, arguments and delivery URL, not the returned ID.
Unsubscribe is idempotent. A subscription ID is a routing handle, not a
credential. TTL expiration stops new attempts; an already transmitted
request cannot be recalled. Refresh and secret rotation never bypass
callback validation.

Arguments support exact `session_id`, `agent` and `task` globs (`*`, `?`), or
an explicit `all_sessions: true`. At least one scope selector is required;
filters combine with AND. An absent label never matches a nonempty label
filter. Discovery returns the argument and payload schemas.

## Event meanings and safe payloads

| Name | Meaning |
|---|---|
| `wardex.question` | A native question was opened. |
| `wardex.approval` | A native approval was requested. Delivery grants no approval. |
| `wardex.done` | A turn finished; its process can remain alive and idle. |
| `wardex.ended` | The process ended; state, exit code and lifecycle reason are separate. |
| `wardex.error` | A turn or session reported an error. |
| `wardex.reminder` | An earlier input request needs attention. Recheck it. |
| `wardex.stuck` | A running session needs attention. |
| `wardex.resolved` | A native request was resolved or cancelled. |

Payloads contain a version, session ID, per-session sequence, driver and
labels (previews capped at 256 characters), plus minimal lifecycle/request fields. They exclude prompts, full
answers, tool input/output, commands, error text, cwd and native transcript
IDs. User-authored labels and other text remain untrusted data. Use tools
to retrieve details after an event arrives; do not turn payload text into
instructions. `done` must never be treated as proof that a process exited.

A question or approval includes `request_id` and `request_seq`. Read current
`pending_questions` before acting and call `answer` with both `question_id`
and `expected_question_seq` from the event. A stale occurrence, an answered
request, an interrupted turn or a reused native ID must not answer a new
question. Legacy callers may omit the optional guard and keep their existing
behavior. Codex native resolution and turn completion invalidate pending
requests. Other write tools retain their existing applied/persisted warnings;
do not resend an action with an uncertain outcome.

## Callback transport and signatures

Only HTTPS destinations without userinfo or fragments are accepted. Every
connection resolves and checks all destination addresses, rejects private,
local, reserved and transition ranges, and pins validated addresses while
retaining hostname/TLS verification. Redirects and inherited proxies are
disabled. The same transport is used for verification and application data;
there is no production localhost bypass. This restriction does not affect
operator-configured generic webhooks.

Before activation, a signed, random, single-use challenge must receive 2xx
and the exact challenge echo. Successful verification is cached for at most
five minutes for an unchanged destination/secret/owner. The process permits
at most 32 new verification attempts per minute. Application data is never
sent to an unverified subscription.

The client supplies a `whsec_` secret encoding 24-64 bytes. Failed refreshes
leave the old subscription intact. Rotation keeps the previous key for five
minutes and includes space-separated Standard Webhooks signatures.

Each request carries one `{eventId, name, timestamp, data, cursor}` object,
`webhook-id` equal to `eventId`, `webhook-timestamp` in Unix seconds,
`webhook-signature` and `X-MCP-Subscription-Id`. The v1 signature is base64
HMAC-SHA256 over `id.timestamp.` followed by the exact body bytes. Body and
ID remain stable across retries; signing time/signature are fresh. The
maximum body is 256 KiB. A 2xx acknowledges receipt, not completion of the
platform's asynchronous task.

## Durability, replay and diagnostics

The original event, minimal journal record and matching outbox rows commit
in one SQLite transaction. Delivery never depends on the live broadcast.
A slow or missing callback does not hold the event writer across network I/O.
Four bounded workers allow independent subscriptions to progress while
serializing deliveries within each subscription.
A full target queue suspends that subscription with `queue_full`, rather
than silently dropping a delivery or blocking the main event writer.

Pending bodies, attempts, due times and claim tokens persist. Restart resets
interrupted claims; expired leases are recoverable. Claim tokens fence old
workers. If the receiver accepted a request but the daemon died before
recording ACK, the same ID/body can arrive again: delivery is at least once.
Consumers must deduplicate event IDs and make resulting actions idempotent.

Network failures, 408, 429 and 5xx retry with capped exponential backoff,
jitter and bounded numeric Retry-After. Attempt count and elapsed window are bounded.
410 stops the subscription; 413 is terminal for that event. Other permanent
responses and exhausted retries suspend delivery with a categorized reason.
No receiver body is exposed as an error oracle.

The journal supplies scoped opaque cursors. Null starts from now, not from
historical completed jobs. Expired/suspended subscriptions can request replay
within retention; active refreshes do not duplicate pending work. A watermark
never skips an unacknowledged delivery. Retention/replay limits report
`truncated: true` and require authoritative-state reconciliation. Disabling
Events stops delivery and journaling; do not assume uninterrupted history
across a period when it was disabled. Pending outbox records survive a restart
while the feature remains enabled. Host power-loss durability is limited by
the existing SQLite WAL `synchronous=NORMAL` setting.

With Events enabled, `overview.mcp_events` reports subscription IDs, names,
active state, expiry, pending count and categorized last error. It never
returns destinations or signing keys. Abandonment and capacity failures are
also logged without sensitive values.

## Migration, deployment and rollback

Migration 0006 is additive and creates Events tables even when the feature
is disabled. It does not convert configured generic webhooks into platform
subscriptions. Existing sessions, events and questions are preserved. Older
binaries with older embedded sqlx migrations can reject this database.
Do not assume replacing only the binary is a valid rollback.

Before deployment: finish isolated checks, plan a graceful drain, resolve
blocking questions, flush state, stop delivery workers, and take a consistent
SQLite backup including WAL state. Keep the previous artifact and a tested,
schema-compatible rollback path. Disable Events with a compatible binary
as the first rollback option. Restoring an older snapshot can lose newer
sessions/events and requires an explicit operational decision. Never force
a drain automatically or change/delete migration history.

Removing a legacy webhook target is an independent operator-config change.
Current generic webhook reload drains an already queued removed target;
removal is not an instant cancellation. Preserve other targets and the
open-source generic webhook implementation. Service enable/linger, tunnel
reboot persistence, Fast/service-tier settings and live installation are
separate operational or development tasks.

## Verification and platform acceptance

Local tests use temporary databases, mock drivers and injected callback
transport. They cover HTTP/stdio discovery and methods, callback challenge
and signature vectors, SSRF address/parser cases, failed rotation, filtered
queues, crash recovery, duplicate IDs, bounded retries and stale input.
No real agent CLI, production daemon/database or platform subscription is
needed for these tests.

An operator must separately prove the platform path with an isolated plugin
and explicitly approved subscription: rescan discovery, verify/subscribe,
start a new matching job, and observe its event and requested reaction in
the intended Work+Cloud/web chat or dot **without status/tail polling**.
Only after arrival may the consumer read summary or current questions.
Also prove question/approval answers, cancelled/reused requests, restart
recovery, duplicate delivery, filters, TTL/refresh/rotation and unsubscribe.
A mock receiver or HTTP 2xx alone does not prove platform event arrival.
Do not repoint an existing production tunnel to a test daemon.
